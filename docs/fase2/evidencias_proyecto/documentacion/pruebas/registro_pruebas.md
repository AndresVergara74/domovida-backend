## Ajustes detectados durante las pruebas

1. La hora de los mensajes ntfy y el conteo de "eventos hoy" usaban hora UTC del servidor (Render) en vez de la hora de Chile (diferencia de 3 horas). Corregido en ntfy (commit 1c8c203, zona America/Santiago); pendiente revisar el conteo "eventos hoy" del panel.
2. La apertura de la puerta principal genera alerta en todos los casos; debería considerar horario o contexto.
3. Una alerta atendida mantiene el color rojo y no muestra la hora de atención.
4. El panel muestra Raspberry Pi y MQTT como "ONLINE", aunque en el prototipo son componentes simulados.
5. El plan gratuito de Supabase pausa el proyecto tras días de inactividad; el backend en Render falla al arrancar hasta reactivarlo (incidente del 01-10-2026).
6. Los despliegues de Vercel fallaban desde el 27-09-2026 por errores de TypeScript (faltaban los tipos de Leaflet y el estado `conectado`); corregido en el commit 9b07078.
7. PR-01: el backend enviaba la notificación ntfy de forma síncrona antes del WebSocket, lo que retrasaba la alerta en el panel. Ajuste aplicado (commit 1c8c203): WebSocket primero y ntfy en segundo plano; latencia promedio bajó de 1.903 ms a 1.577 ms (−17 %). La latencia restante se explica por la distancia entre servicios (navegador en Chile → backend en Oregón → base de datos en São Paulo), propia de los planes gratuitos; la meta < 1 s requiere acercar las regiones (backend y base de datos en la misma región) en una fase de producción.
8. ntfy en Android: con la optimización de batería activa, las notificaciones llegan con retraso aunque el servidor las acepte. Mitigación: permitir uso en segundo plano y entrega instantánea en la app ntfy; documentarlo en el manual del cuidador.
9. PS-01 (autenticación de endpoints) no se ejecutó: al revisar el código se constató que la API REST no implementa autenticación (no hay token ni clave), por lo que cualquier cliente autorizado por CORS puede enviar datos o marcar alertas como atendidas. Hallazgo de seguridad: se planifica agregar una clave de API para los sensores y autenticación para el panel (Supabase Auth) antes del cierre del prototipo. La protección actual de los datos almacenados descansa en RLS (PI-03 aprobada) y en CORS.
